Baksa Tales: frontend delivery report

Implemented the approved ZIP’s HTML screens in the existing website, using their original markup, inline styling, fonts, logos, product photographs and wording. Added working browser-only sample interactions rather than connecting live services.

Demo only. A visible “Sample data” notice and Reset demo data control are available throughout. Nothing is charged or submitted to a live business service. Browser storage is not a production database.

Still requires real services before launch

  • Supabase: production data, accounts, sign-in, roles, listing permissions, orders, inventory, payouts, enquiries and reliable cross-device persistence. Existing backend files remain, but this demo does not call them.
  • Authentication and SMS: phone verification, actual SMS codes, sessions, abuse protection and account recovery. The demo accepts any 10 digits and any four-digit code.
  • Payment gateway: checkout, webhooks, refunds, tax/fee confirmation, reconciliation and actual bank payouts. “Pay” and “Mark as paid” are simulations.
  • PIN code lookup: real city/state and delivery serviceability. The supplied rough PIN helper is prototype-only.
  • Couriers: booking, labels, tracking events, delivery confirmation and return handling. Courier/tracking input is required before the sample Packed order becomes On the way.
  • Zoho CRM: corporate brief sync, assignments, maker outreach and quote delivery.
  • WhatsApp and contact services: opt-in, message delivery, approved contact/social destinations and support. Share opens WhatsApp’s composer; it does not send automatically.
  • TagMango: real live bookings, seats, recorded-course purchases/access and reporting. Demo bookings, proposals and CSV checks are not live integrations.
  • Analytics consent: consent controls and production measurement; the demo does not wire the old app’s analytics to these new screens.
  • Confirmed business content: shipping/returns/support policies and any existing placeholders, unverified prices or delivery statements must be confirmed before launch. No new commercial promises were added.

No production database, DNS, live website or payment account was changed. The site has not been published.
